Q1. K-map simplification, PI and EPI

F(A,B,C,D) = Σm(0,1,2,5,8,9,10)

        CD
AB     00  01  11  10
 00     1   1   0   1

Groups: - m0,1,8,9 → B'C' - m0,2,8,10 → B'D' - m1,5 → A'C'D

All three are prime implicants (can't be enlarged). Each covers a minterm no other covers (B'C' → m9, B'D' → m2/m10, A'C'D → m5), so all three are essential PIs.

Q2. Don't cares

Q3. Definitions

  • Implicant: a product term (group of 1s) of the function.
  • Prime implicant (PI): an implicant that can't be combined with another to form a larger group (the biggest possible group).
  • Essential PI (EPI): a PI that covers at least one minterm covered by no other PI; it must appear in the minimal expression.
  • Incompletely specified function: output is "don't care" (X/d) for some input combinations that never occur. In K-maps a d can be treated as 1 or 0, whichever gives larger groups. Example: Q2.

Q4. POS form using K-map

For the function in Q1, group the 0s (m3,4,6,7,11,12,13,14,15): - m4,6,12,14 → BD'; m3,7,11,15 → CD; m12–15 → AB

F' = BD' + CD + AB → complement with De Morgan:

F = (B' + D)(C' + D')(A' + B')

Q5. NAND-only / NOR-only implementation

  • SOP → NAND-NAND: F = AB + CD = ((AB)'·(CD)')' → three 2-input NAND gates: N1 = NAND(A,B), N2 = NAND(C,D), F = NAND(N1,N2).
  • POS → NOR-NOR: F = (A+B)(C+D) = ((A+B)' + (C+D)')' → N1 = NOR(A,B), N2 = NOR(C,D), F = NOR(N1,N2).
  • Method for multilevel: replace every AND/OR by NAND/NAND (or NOR/NOR), add inverters wherever a literal enters at a wrong level, and double-bubble cancel.

Q6. Universality of NAND (NOR is the dual)

  • NOT: A' = (A·A)' (tie inputs)
  • AND: AB = ((AB)')' → NAND followed by NAND-as-inverter
  • OR: A + B = (A'·B')' → NAND(NAND(A,A), NAND(B,B))

Since {AND, OR, NOT} can be built, NAND is universal. NOR: NOT = NOR(A,A), OR = NOT(NOR), AND = NOR(A',B').

Q8. Half adder and full adder

Half adder (adds 2 bits): S = A⊕B, C = A·B (one XOR + one AND).

Full adder (adds A, B, Cin): | A B Cin | S | Cout | |-|-|-| | 000 | 0 | 0 | | 001 | 1 | 0 | | 010 | 1 | 0 | | 011 | 0 | 1 | | 100 | 1 | 0 | | 101 | 0 | 1 | | 110 | 0 | 1 | | 111 | 1 | 1 |

S = A⊕B⊕Cin, Cout = AB + Cin(A⊕B)

From two half adders: HA1 adds A,B → S1, C1. HA2 adds S1, Cin → S, C2. Cout = C1 + C2 (OR gate).

Q9. 4-bit ripple carry adder

Four full adders in cascade: Cout of stage i feeds Cin of stage i+1.

A3 B3   A2 B2   A1 B1   A0 B0
 |  |    |  |    |  |    |  |
[FA3]←C3[FA2]←C2[FA1]←C1[FA0]←C0(Cin)
 S3      S2      S1      S0       (C4 = final carry out)

Drawback: carry must ripple through all stages: total delay ≈ n × (carry delay of one FA) → slow for large n. Fix: carry look-ahead adder (Gi = AiBi, Pi = Ai⊕Bi, C(i+1) = Gi + PiCi).

Q10. Adder/Subtractor

Use one 4-bit adder with XOR gates on B inputs and mode M: - Bi' = Bi ⊕ M, and Cin = M - M=0: A + B. M=1: A + (B' ) + 1 = A − B (2's complement). - Overflow (signed) V = C4 ⊕ C3 (carry into MSB XOR carry out of MSB). Overflow occurs when two operands of the same sign give a result with the opposite sign.

Q11. BCD adder

Add two BCD digits with a 4-bit binary adder → sum Z3Z2Z1Z0 and carry K'. If the result is > 9 or a carry is produced, add 0110 (6) to correct it, with a second 4-bit adder.

Correction condition: C = K' + Z3Z2 + Z3Z1 - Output carry = C; if C=1 the second adder adds 0110, else 0000.

Example: 8 + 5: 1000+0101 = 1101 (13) → Z3Z2=1 → C=1 → 1101+0110 = 1 0011 → BCD 13 ✓ (carry 1, digit 3).

Why 6: a 4-bit nibble has 16 values but BCD uses 10; adding 6 skips the 6 invalid codes.

Q12. 4-bit magnitude comparator

Define xi = Ai ⊙ Bi (XNOR) → bit equal. - (A = B) = x3 x2 x1 x0 - (A > B) = A3B3' + x3A2B2' + x3x2A1B1' + x3x2x1A0B0' - (A < B) = A3'B3 + x3A2'B2 + x3x2A1'B1 + x3x2x1A0'B0

Compare from MSB; the first unequal bit decides.

Q13. 4×4 array multiplier

Multiplicand a3a2a1a0, multiplier b3b2b1b0. - Partial products ai·bj generated by 16 AND gates. - Rows are shifted and added with an array of half/full adders (about 4 HA + 8 FA) arranged in rows; carries propagate diagonally/down. - Output P7..P0. Combinational, fast, regular layout, but area grows as n².

Q14. Verilog full adder and 4-bit ripple adder

module fulladd(input a, b, cin, output s, cout);
  assign s    = a ^ b ^ cin;              // dataflow
  assign cout = (a & b) | (cin & (a ^ b));
endmodule

module add4(input [3:0] a, b, input cin, output [3:0] s, output cout);
  wire c1, c2, c3;                         // structural
  fulladd f0(a[0], b[0], cin, s[0], c1);
  fulladd f1(a[1], b[1], c1,  s[1], c2);
  fulladd f2(a[2], b[2], c2,  s[2], c3);
  fulladd f3(a[3], b[3], c3,  s[3], cout);
endmodule

Behavioural one-liner: assign {cout, s} = a + b + cin;

Q16. Implement function with 4:1 MUX

F(A,B,C) = Σm(1,2,6,7), use A,B as selects, C as data:

AB minterms F MUX input
00 m0,m1 C I0 = C
01 m2,m3 C' I1 = C'
10 m4,m5 0 I2 = 0
11 m6,m7 1 I3 = 1

Connect S1=A, S0=B. (An 8:1 MUX would just tie I1,I2,I6,I7 = 1 and the rest = 0.)

Q17. 16:1 MUX using 4:1 MUXes

Use 5 4:1 MUXes: first level 4 MUXes, each takes 4 of the 16 inputs and shares select lines S1S0; the second-level MUX takes their four outputs and uses S3S2 as selects. Output = selected input.

Q18. 3:8 decoder and decoder tree

3:8 decoder with enable: Yi = E · (minterm i of A2A1A0), e.g., Y5 = E·A2A1'A0 → 8 AND gates (3-input, with E 4-input) + 3 inverters.

4:16 decoder from two 3:8 decoders: A3 drives the enable: decoder 1 enable = A3', decoder 2 enable = A3; A2A1A0 go to both. Outputs: D0–D7 from first, D8–D15 from second. (Alternatively 5 × 2:4 decoders: one for A3A2 enabling four others for A1A0.)

Q19. Function using decoder + OR

Full adder using a 3:8 decoder (inputs A,B,Cin): - S = Σm(1,2,4,7) → OR of Y1,Y2,Y4,Y7 - Cout = Σm(3,5,6,7) → OR of Y3,Y5,Y6,Y7

(If the decoder has active-low outputs, use NAND gates instead of OR.)

Q20. Encoders

4:2 encoder (one-hot input): | D3 D2 D1 D0 | Y1 Y0 | |-|-| | 0001 | 00 | | 0010 | 01 | | 0100 | 10 | | 1000 | 11 |

Y1 = D2 + D3, Y0 = D1 + D3.

Priority encoder (D3 highest priority; X = don't care) with valid bit V: | D3 D2 D1 D0 | Y1 Y0 | V | |-|-|-| | 0000 | XX | 0 | | 0001 | 00 | 1 | | 001X | 01 | 1 | | 01XX | 10 | 1 | | 1XXX | 11 | 1 |

Y1 = D3 + D2, Y0 = D3 + D2'D1, V = D3+D2+D1+D0. Solves the problem of multiple simultaneous inputs.

Q21. Verilog 4:1 MUX

// (a) if-else
module mux4_if(input [3:0] I, input [1:0] S, output reg Y);
  always @(*) begin
    if      (S == 2'b00) Y = I[0];
    else if (S == 2'b01) Y = I[1];
    else if (S == 2'b10) Y = I[2];
    else                 Y = I[3];
  end
endmodule

// (b) case
module mux4_case(input [3:0] I, input [1:0] S, output reg Y);
  always @(*) begin
    case (S)
      2'b00: Y = I[0];
      2'b01: Y = I[1];
      2'b10: Y = I[2];
      2'b11: Y = I[3];
    endcase
  end
endmodule

Q22. Verilog 2:4 decoder with enable

module dec2to4(input [1:0] A, input E, output reg [3:0] Y);

Q23. always block, sensitivity list, assign vs always

  • always @(sensitivity list) is a procedural block: executes whenever a signal in the list changes. Statements inside (if, case, loops) run sequentially, and only reg variables may be assigned.
  • Combinational logic: always @(*) (all inputs), blocking =, and assign every output in all branches (else a latch is inferred).
  • Sequential logic: always @(posedge clk) with non-blocking <=.
assign always
Continuous assignment Procedural
Drives wire Drives reg
Single expression Multiple statements, if/case

Q24. Verilog module structure & modelling styles

module name (port list);
  input / output declarations
  wire / reg declarations
  body (gate, assign, always, instances)
endmodule
  • wire: connection; driven by assign/gate/module output; no storage.
  • reg: variable assigned inside always/initial; holds value (becomes a flip-flop or just combinational logic depending on the block).
  • Gate-level: and g1(y,a,b);
  • Dataflow: assign y = a & b;
  • Behavioural: always @(*) if(...) ...
  • Structural: instantiation of lower-level modules.

Q26. Latches

SR latch (NOR): cross-coupled NOR gates. S=R=0 hold; S=1,R=0 set (Q=1); S=0,R=1 reset (Q=0); S=R=1 invalid (both outputs 0, unpredictable on release). SR latch (NAND): inputs are active-low: S'R' = 11 hold, 01 set... (S'=0 sets), 10 reset, 00 invalid.

Gated SR latch: adds two AND/NAND gates with an enable (clock) C: latch responds only when C=1.

Gated D latch: D drives S, D' drives R (removes the invalid state). When C=1: Q = D (transparent); when C=0: holds.

C D Q+
0 X Q
1 0 0
1 1 1

Q27. D, T, JK flip-flops

FF Truth table Characteristic equation
D D=0→Q+=0; D=1→Q+=1 Q+ = D
T T=0 hold; T=1 toggle Q+ = T ⊕ Q
JK 00 hold, 01 reset, 10 set, 11 toggle Q+ = JQ' + K'Q
SR 00 hold, 01 reset, 10 set, 11 invalid Q+ = S + R'Q, SR = 0

Race-around in JK: with J=K=1 and level-triggered clock, if clock-high time > propagation delay, output toggles repeatedly during one pulse → uncertain final state. Master-slave solution: two latches in series with opposite clock phases. Master samples while CLK=1, slave updates only when CLK=0, so output changes once per clock cycle. (Edge-triggering is the other solution.)

Q28. Latch vs flip-flop

Latch Flip-flop
Level-sensitive (transparent while enable active) Edge-triggered (samples at a clock edge)
Output may change many times during enable Changes only at the active edge
Fewer gates Built from two latches (master-slave)

Q29. Conversions (use excitation tables)

JK excitation: Q→Q+ : 0→0: J=0,K=X; 0→1: J=1,K=X; 1→0: J=X,K=1; 1→1: J=X,K=0. - JK → D: J = D, K = D' (one inverter). - JK → T: J = K = T. - D → T: D = T ⊕ Q.

Q30. Shift registers

n flip-flops in series, same clock; data moves one position per clock. - SISO: serial in, serial out (delay line). - SIPO: serial in, outputs of all FFs read in parallel (serial→parallel conversion). - PISO: parallel load via a Shift/Load control (MUX before each FF), then shifted out serially. - PIPO: all bits loaded and read simultaneously (basic register).

Din → [D FF0] → [D FF1] → [D FF2] → [D FF3] → Dout
        ↑CLK     ↑CLK       ↑CLK       ↑CLK
Q0..Q3 = parallel outputs (SIPO)

Q31. Ring and Johnson counters

Ring counter (4 bits): Q3 feeds back to D0; preset to 1000. Sequence: 1000 → 0100 → 0010 → 0001 → 1000 (mod-4, n FFs → n states)

Johnson (twisted-ring) counter: inverted output Q3' feeds D0; start 0000. Sequence: 0000 → 1000 → 1100 → 1110 → 1111 → 0111 → 0011 → 0001 → 0000 (mod-8, n FFs → 2n states)

Ring Johnson
States (n FFs) n 2n
Decoding None (one-hot) 2-input AND per state
Self-starting No No

Q32. 3-bit synchronous up/down counter (T flip-flops)

Control M (M=1 up, M=0 down). A T flip-flop toggles when its T input = 1. - Up: Q0 toggles always; Q1 toggles when Q0=1; Q2 toggles when Q1Q0=1. - Down: Q1 toggles when Q0=0; Q2 toggles when Q1'Q0'=1.

T0 = 1 T1 = M·Q0 + M'·Q0' T2 = M·Q1Q0 + M'·Q1'Q0'

All FFs share one clock (synchronous). For JK flip-flops use J = K = T. Design steps shown: state table (present → next state) → excitation values T = Q ⊕ Q+ → K-map each T → circuit.

Sequence 000 → 001 → 010 → 011 → 100 → 101 → 000 (110, 111 = don't care).

Q34. Asynchronous (ripple) counter

4-bit ripple counter: four T/JK (J=K=1) flip-flops; CLK drives FF0; each next FF is clocked by the previous Q (negative-edge triggered FFs). Counts 0000 → 1111 (mod-16).

Q35. Ring counter via counter + decoder

Use a 2-bit binary counter driving a 2:4 decoder: as the counter counts 00,01,10,11 the decoder outputs 0001, 0010, 0100, 1000 → a one-hot ring sequence using only 2 FFs instead of 4 (n-state ring needs log2(n) FFs plus a decoder).

Q38. Design steps for synchronous sequential circuits

  1. Word description → state diagram.
  2. State table (present state, input → next state, output); minimise states.
  3. State assignment (binary encode states).
  4. Choose flip-flop type and derive excitation table.
  5. Simplify flip-flop input equations and output equations using K-maps.
  6. Draw the logic circuit; verify by simulation.

Q39. Verilog D flip-flop with clear

// Synchronous clear: reset sampled only at clock edge
module dff_sync(input D, clk, clr, output reg Q);
  always @(posedge clk)
    if (clr) Q <= 1'b0;
    else     Q <= D;
endmodule

// Asynchronous clear: reset acts immediately
module dff_async(input D, clk, clr, output reg Q);
  always @(posedge clk or posedge clr)
    if (clr) Q <= 1'b0;
    else     Q <= D;
endmodule

Difference: asynchronous reset is in the sensitivity list.

Q40. Blocking vs non-blocking

  • Blocking (=): evaluated and assigned immediately, in order; next statement waits. Use for combinational logic.
  • Non-blocking (<=): RHS evaluated now, all assignments updated at the end of the time step. Use for sequential logic.

Example (shift):

always @(posedge clk) begin  q1 <= d;  q2 <= q1;  end   // 2-stage shift register
always @(posedge clk) begin  q1 =  d;  q2 =  q1;  end   // q2 gets d, → collapses to one FF (wrong)

Rule: <= in clocked blocks, = in combinational blocks; don't mix in one block.

Q41. Register, shift register, counter

// n-bit register with load and reset
module reg_n #(parameter N=8)(input clk, rst, load, input [N-1:0] D, output reg [N-1:0] Q);
  always @(posedge clk or posedge rst)
    if (rst) Q <= 0;

// 4-bit shift register (SIPO)
module shreg(input clk, rst, din, output reg [3:0] Q);
  always @(posedge clk or posedge rst)
    if (rst) Q <= 4'b0;
    else Q <= {Q[2:0], din};
endmodule

// 4-bit up counter with load and reset
module counter(input clk, rst, load, input [3:0] D, output reg [3:0] Q);
  always @(posedge clk or posedge rst)
    if (rst) Q <= 4'b0;
    else if (load) Q <= D;
    else Q <= Q + 1;
endmodule

Q42. Verilog FSM – 1011 detector (Mealy)

module seq1011(input clk, rst, x, output reg z);
  parameter S0=2'b00, S1=2'b01, S2=2'b10, S3=2'b11;
  reg [1:0] state, next;

  always @(posedge clk or posedge rst)        // state register
    if (rst) state <= S0; else state <= next;

  always @(*) begin                            // next-state + output logic
    z = 0;
    case (state)
      S0: next = x ? S1 : S0;
      S1: next = x ? S1 : S2;
      S2: next = x ? S3 : S0;
      S3: begin next = x ? S1 : S2; z = x; end
      default: next = S0;
    endcase
  end
endmodule

UNIT 3 – Instruction Set Architecture (CO5)

Q43. Memory addressing, endianness

  • Memory = sequence of locations, each with a unique address (0 … 2^k − 1 for k-bit address).
  • Byte-addressable: each address names one byte; a 32-bit word occupies 4 consecutive addresses and is addressed by its lowest address.
  • Word 0x12345678 stored at address 1000:
Address 1000 1001 1002 1003
Big-endian (MSB at lowest address) 12 34 56 78
Little-endian (LSB at lowest address) 78 56 34 12

Q44. Memory operations, alignment

  • Load (Read): copies a word from memory to a processor register; the memory content is unchanged. Address → MAR, Read control, data returns in MDR.
  • Store (Write): copies a register's contents into a memory location, overwriting the old contents.
  • Alignment: a word is aligned if its address is a multiple of the word length (e.g., multiple of 4 for 32 bits). Unaligned access is restricted or slower in many architectures.

Q45. Instruction types, sequencing, program

Instruction types: data transfer (Move, Load, Store), arithmetic/logic (Add, Sub, AND), control/branch (Branch, Call, Return), I/O.

Sequencing: PC holds the address of the next instruction. Straight-line sequencing executes consecutively (PC ← PC + 4). Branch instructions load a new target into PC; conditional branches test condition code flags (N, Z, V, C) set by previous ALU operations, e.g., Branch>0 LOOP.

Program: add N numbers (list starts at NUM1, count in N, result in SUM):

        Move    N, R1          ; R1 = count
        Clear   R0             ; R0 = running sum
        Move    #NUM1, R2      ; R2 = pointer to list
LOOP:   Add     (R2)+, R0      ; R0 += next number, pointer++
        Decrement R1
        Branch>0 LOOP
        Move    R0, SUM

UNIT 4 – Arithmetic & Control Unit (CO3)

Q50. Booth's algorithm: (+7) × (−3)

Algorithm (n-bit): registers A = 0, Q = multiplier, Q₋₁ = 0, M = multiplicand, count = n. Repeat n times, look at (Q0, Q₋₁): - 10 → A = A − M - 01 → A = A + M - 00 or 11 → no operation

then arithmetic shift right A, Q, Q₋₁ together (sign of A preserved).

M = 0111 (+7), Q = −3 = 1101, −M = 1001. 4 bits.

Cycle Q0Q₋₁ Operation A Q Q₋₁
init 0000 1101 0
1 10 A = A − M 1001 1101 0
ASR 1100 1110 1
2 01 A = A + M 0011 1110 1
ASR 0001 1111 0
3 10 A = A − M 1010 1111 0
ASR 1101 0111 1
4 11 no op 1101 0111 1
ASR 1110 1011 1

Result AQ = 1110 1011 = −21 ✓

Q51. Why Booth? Bit-pair recoding

  • Handles signed (2's complement) numbers directly, no sign correction.
  • A string of 1s in the multiplier (…0111…10…) = 2^(k+1) − 2^j: needs only one subtraction at the start of the string and one addition after it, so runs of 1s are skipped: fewer additions when the multiplier has long runs.

Bit-pair (radix-4) recoding: look at three bits (b(i+1), b(i), b(i−1)); halves the number of partial products to n/2.

b(i+1) b(i) b(i−1) Multiplier action
000 0
001 +1 × M
010 +1 × M
011 +2 × M
100 −2 × M
101 −1 × M
110 −1 × M
111 0

Q52. Restoring division: 15 ÷ 4

Algorithm (n bits): A = 0, Q = dividend, M = divisor. Repeat n times: 1. Shift A,Q left one bit. 2. A = A − M. 3. If A < 0 (sign bit 1): set q0 = 0 and restore A = A + M. Else q0 = 1.

Q = 1111 (15), M = 00100 (4), A = 00000:

Step After shift (A,Q) A − M Action A Q
1 00001, 111_ 11101 (neg) restore, q0=0 00001 1110
2 00011, 110_ 11111 (neg) restore, q0=0 00011 1100
3 00111, 100_ 00011 keep, q0=1 00011 1001
4 00111, 001_ 00011 keep, q0=1 00011 0011

Quotient = 0011 = 3, Remainder = 00011 = 3 (15 = 4×3 + 3 ✓)

Non-restoring: no restore step. After shift: if A ≥ 0 then A = A − M, else A = A + M; q0 = 1 if the new A ≥ 0 else 0. At the end, if A < 0, add M once to correct the remainder. Fewer operations per cycle.

Q54. Floating-point addition

Steps: (1) compare exponents; (2) shift the mantissa of the smaller number right by the difference; (3) add/subtract mantissas; (4) normalise (shift, adjust exponent); (5) round; check overflow/underflow.

Example: 9.75 + 0.5625 - 9.75 = 1.00111 × 2³; 0.5625 = 1.001 × 2⁻¹ - Exponent difference = 4 → shift second mantissa right 4: 0.0001001 × 2³ - Add: 1.0011100 + 0.0001001 = 1.0100101 × 2³ (already normalised) - = 1010.0101₂ = 10.3125 ✓

Q55. FP multiplication/division, special values, rounding

  • Multiply: add exponents (subtract bias once), multiply mantissas, XOR signs, normalise, round. Divide: subtract exponents (add bias), divide mantissas.
  • Special values (single precision):
Exponent Fraction Meaning
0 0 ±0
0 ≠0 Denormal (0.M × 2⁻¹²⁶)
255 0 ±∞
255 ≠0 NaN
  • Guard bits (extra bits G, R, sticky) kept during alignment shift to preserve accuracy before rounding.
  • Rounding modes: round to nearest even (default), toward 0 (truncate), toward +∞, toward −∞.

Q56. Processing section (datapath) of Booth multiplier

Components: - M register (multiplicand), n bits - A register (accumulator, upper product) with parallel load and arithmetic shift right - Q register (multiplier / lower product) shift right; LSB Q0 - Q₋₁ flip-flop (receives the bit shifted out of Q0) - n-bit adder/subtractor (A ± M; subtract = add 2's complement) - Counter C initialised to n, decremented every cycle; Z = count finished flag

   M ───────┐
            ▼
         [Adder/Sub] ←(Add/Sub control)
            ▲  │
   A ───────┘  ▼ (load A)
   A ──► ASR chain: A → Q → Q-1
   Q0, Q-1 → controller     Z (counter=0) → controller

Control signals: Load M, Init (A←0, Q₋₁←0, C←n), AddM, SubM, Shift (ASR + decrement C), Done. Status inputs: Q0, Q₋₁, Z.

Q57. Hardwired controller for Booth multiplier

State/ASM chart:

State Action Next
S0 Idle, wait Start=1 → S1
S1 Init: A←0, Q₋₁←0, C←n, load M,Q S2
S2 Decision on Q0Q₋₁ 01 → S3; 10 → S4; 00/11 → S5
S3 A ← A + M S5
S4 A ← A − M S5
S5 ASR(A,Q,Q₋₁); C ← C−1 Z=1 → S6; else S2
S6 Done=1 S0

Control outputs: Init = S1, Add = S3, Sub = S4, Shift/Dec = S5, Done = S6.

One flip-flop per state (one-hot) equations: - D(S0) = S0·Start′ + S6 - D(S1) = S0·Start - D(S2) = S1 + S5·Z′ - D(S3) = S2·Q0′·Q₋₁ - D(S4) = S2·Q0·Q₋₁′ - D(S5) = S2·(Q0 ⊙ Q₋₁) + S3 + S4 - D(S6) = S5·Z

(Z is the counter's terminal-count flag, i.e., this S5 pass is the nth shift.) Implemented with gates + flip-flops (or a sequence counter + decoder): fast, but fixed hardware.

Q58. Micro-programmed control organization

  • Microinstruction: a control word specifying which control signals are asserted in one clock step (+ next-address info).
  • Microprogram: sequence of microinstructions implementing one machine instruction; stored in control store (ROM).
  • Organization: IR → Starting-address generator → µPC (µAR) → Control store → Microinstruction register (µIR) → control signals to datapath. µPC normally increments; branches load new address from the address field/starting-address generator, using condition codes/status.
  • Execution: fetch microinstruction → decode/issue control signals → compute next µPC.

Q59. Wilkes' design

Early microprogram design. Control store is a two-section matrix (diode array) plus a register: - Matrix A: each row = one microinstruction's control signals (a 1 at a crosspoint asserts the signal). - Matrix B: each row = address of the next microinstruction. - A microinstruction address register + decoder selects exactly one row. - Conditional branching: an external condition bit is ORed with the low bits of the next-address to choose between two successor addresses. - A clock pulse (two-phase) loads the next address into the register and applies the control signals to the datapath.

Advantage: simple, regular structure; the control sequence changes by changing the matrix contents.

Q63. Instruction execution and single-bus datapath

Cycle: Fetch → Decode → Execute → (Write-back/Store).

Fetch (every instruction): 1. PC_out, MAR_in, Read, Select4, Add, Z_in 2. Z_out, PC_in, Y_in, WMFC (wait for memory) 3. MDR_out, IR_in

UNIT 5 – Memory, I/O & Parallel Processing (CO4)

Q64. Cache memory, locality, hit ratio

  • Cache: small, fast memory between CPU and main memory holding recently used instructions/data.
  • Locality of reference:
  • Temporal: recently used items will likely be used again soon (loops).
  • Spatial: items near a recently used address will likely be used soon (sequential code, arrays) → whole blocks are fetched.
  • Hit = requested word found in cache; miss = not found (fetch block from memory).
  • Hit ratio h = hits / total accesses; miss rate = 1 − h.

Q66. Numerical: address field breakup and hit/miss trace

Given: Main memory 64K words (16-bit address), cache 1K words, block 16 words. - Word field = log2(16) = 4 bits. Cache lines = 1K/16 = 64. - Direct: block field = 6, tag = 16 − 6 − 4 = 6 → Tag(6) | Block(6) | Word(4) - Associative: tag = 16 − 4 = 12 → Tag(12) | Word(4) - 4-way set-associative: sets = 64/4 = 16 → set field 4, tag = 16 − 4 − 4 = 8 → Tag(8) | Set(4) | Word(4)

(Formula: tag = address bits − index bits − offset bits.)

Trace: cache of 4 blocks, block-address sequence 0, 8, 0, 6, 8 - Direct mapped (line = addr mod 4): 0→L0 miss; 8→L0 miss (evicts 0); 0→L0 miss; 6→L2 miss; 8→L0 miss. 0 hits, 5 misses. - 2-way set-associative, LRU (set = addr mod 2): 0 miss [S0:0]; 8 miss [0,8]; 0 hit; 6 miss (evict LRU 8) [0,6]; 8 miss (evict 0). 1 hit, 4 misses.

Q67. Replacement strategies

  • FIFO: replace the block that has been in the cache longest.
  • LRU: replace the least recently used block (best approximation of optimal; implemented with counters/age bits).
  • Random: replace a random block (simple, performs surprisingly well).

Reference string 7,0,1,2,0,3,0,4,2,3,0,3,2 with 3 frames: - FIFO: 7M 0M 1M 2M(evict 7) 0H 3M(evict 0) 0M(evict 1) 4M(evict 2) 2M(evict 3) 3M(evict 0) 0M(evict 4) 3H 2H → 10 misses, 3 hits - LRU: 7M 0M 1M 2M(evict 7) 0H 3M(evict 1) 0H 4M(evict 2) 2M(evict 3) 3M(evict 0) 0M(evict 4) 3H 2H → 9 misses, 4 hits

Q68. Write policies, AMAT

  • Write-through: every write updates both cache and main memory. Memory always consistent, simple, but more memory traffic (write buffer helps).
  • Write-back (copy-back): write only the cache; set a dirty bit; write block to memory only when replaced. Less traffic; memory may be stale (matters for I/O and multiprocessors).
  • AMAT = hit time + miss rate × miss penalty Example: hit time 2 ns, h = 0.95, memory penalty 50 ns → AMAT = 2 + 0.05 × 50 = 4.5 ns.

Q69. Cache coherence

Problem: in a multiprocessor each processor has a private cache, so copies of the same block can become inconsistent. - Write-through protocol: a write goes to memory; other caches holding that block must be invalidated (or updated) so they don't use stale data. - Write-back protocol: a writer first obtains ownership: other copies are invalidated; block marked modified/dirty; other processors' reads are served from the owner's cache (or after write-back). - Snooping (bus-based) or directory-based mechanisms detect writes to shared blocks.

  • Program-controlled I/O (polling): processor repeatedly tests the status flag (e.g., input ready/SIN) in a loop, then reads/writes the data register. Simple but wastes CPU time on waiting.

Q71. Interrupts

  • Device sends an interrupt request when ready; processor finishes the current instruction, saves PC/status, runs the interrupt-service routine (ISR), then returns (Return-from-interrupt).
  • Handling: (1) acknowledge, (2) save context, (3) identify the source, (4) execute ISR, (5) restore and resume. Interrupts can be enabled/disabled.
  • Vectored interrupts: device supplies a vector (address of ISR) directly → fast source identification. Non-vectored: software polls devices.
  • Priority: simultaneous requests resolved by priority (daisy chain or priority encoder); higher priority can nest.
  • Interrupt latency = delay between request and the start of the ISR.

Q72. DMA (brief)

A DMA controller transfers a block of data between I/O device and memory without CPU involvement per word. CPU programs the DMA with start address, word count and direction; DMA acquires the bus (cycle stealing or burst), transfers, and interrupts CPU when finished. Best for high-speed block transfers.

Q73. Pipelining

  • Pipelining overlaps instruction execution by dividing it into stages; each stage works on a different instruction in the same clock cycle → throughput of ≈ one instruction per cycle.
  • 5-stage pipeline: IF (fetch) → ID (decode/register read) → EX (ALU) → MEM (memory access) → WB (write-back). Pipeline registers separate stages.
Cycle 1 2 3 4 5 6
I1 IF ID EX MEM WB
I2 IF ID EX MEM WB
  • Hazards:
  • Structural: two instructions need the same hardware resource. Fix: duplicate resources (separate I/D caches).
  • Data: instruction depends on result of an earlier one (RAW). Fix: forwarding/bypassing, stalls (NOP), compiler scheduling.
  • Control: branches change PC. Fix: branch prediction, delayed branch, flush.

Q74. Pipeline speed-up

For k stages, n tasks, clock period tp: - Non-pipelined time = n · k · tp - Pipelined time = (k + n − 1) · tp - Speed-up S = nk / (k + n − 1) → k as n → ∞ - Throughput = n / ((k + n − 1) tp)

Example: k = 5, n = 100: pipelined = 104 cycles, non-pipelined = 500 → S = 500/104 ≈ 4.81, throughput ≈ 0.96 instr/cycle.

Q75. Vector processing

  • Vector processor operates on arrays (vectors) with a single instruction (e.g., C[i] = A[i] + B[i] for all i).
  • Uses deep pipelined functional units and vector registers; one instruction fetch/decode amortised over many elements.
  • Advantages: high throughput for scientific/graphics/ML numeric loops, fewer instructions fetched, no loop overhead or branch hazards, regular memory access (good bandwidth). Examples: Cray, SIMD extensions (AVX).
